## GITLAB_TOKEN Expiration Warning

The `GITLAB_TOKEN` used for pipeline automation expires in **{days_left} days** on **{expires_at}**.

### Impact

When the token expires, ALL pipelines will FAIL!

### Token Rotation Steps

**1. Create new Personal Access Token:**
- Go to **Settings → Access Tokens**
- Delete the old `GITLAB_TOKEN`
- Click "Add new token"
- Configure token:
  - **Name:** `GITLAB_TOKEN`
  - **Expiration date:** Set to maximum allowed (typically 365 days)
  - Set to Maintainer role
  - **Scopes:** Checkmark **all available scopes** to avoid permission issues
- Click "Create personal access token"
- **Copy the token immediately** - it won't be shown again

**2. Update SOPS-encrypted secrets file:**

This repo stores `GITLAB_TOKEN` in `.sops.env` (NOT as CI/CD variable).

```bash
# Edit encrypted file (auto-decrypts, auto-encrypts on save)
sops .sops.env
# Update the GITLAB_TOKEN value
# Save and exit
```

Or manually:
```bash
sops -d .sops.env > /tmp/secrets.env
# Edit /tmp/secrets.env with new token
sops -e /tmp/secrets.env > .sops.env
rm /tmp/secrets.env
```

**3. Commit and push:**
```bash
git add .sops.env
git commit -m "Rotate GITLAB_TOKEN"
git push
```

**4. Verify:**
The new token's expiration will be automatically detected on the next scheduled check. This issue will auto-close when the token has > 30 days remaining.

### Troubleshooting

**Token scope requirements:**
The token needs many scopes to allow all pipeline operations. If you encounter permission errors in pipelines after rotation, ensure the token has all scopes enabled.
